Visión general del sistema

Luna Workspace está compuesto por dos partes que conviven en el mismo servidor:

🔌 Plugin de WordPress

Instala la app en WP y expone una página de administración para gestionar usuarios y configurar notificaciones.

Ruta: /wp-content/plugins/luna-workspace/

🖥️ Aplicación Luna (SPA)

La app real: un tablero Kanban + Calendario + Chat. Es PHP + HTML/JS puro, independiente de WordPress.

Ruta: /luna-workspace/app/

¿Por qué dos bases?

El plugin se instaló en WordPress y WordPress crea sus propias tablas con prefijo wp_luna_*. Pero la app real corre como app PHP independiente y usa admin_luna sin prefijo. El panel de administración de WordPress fue modificado para leer directamente de admin_luna usando PDO (conexión directa), porque si no, solo veía sus propias tablas vacías.

¿Cómo funciona la autenticación en cada request?

Cada llamada a la API envía el token en el header:

Authorization: Bearer TOKEN_AQUI
X-Workspace-Id: 1

En el backend, config.php tiene:

function requireAuth() {
    $token = str_replace('Bearer ', '', $_SERVER['HTTP_AUTHORIZATION'] ?? '');
    // busca el token en la tabla sessions
    $st = $db->prepare("SELECT u.* FROM sessions s JOIN users u ON u.id=s.user_id WHERE s.token=? AND s.expires_at > NOW()");
    // si no existe → jsonErr('No autenticado', 401)
}

Tipos de notificación

assigned — Al asignar

Mensaje completo: estado, descripción, prioridad, quién asigna, fechas, tags. Se envía solo a los NUEVOS asignados.

updated — Al modificar

Mensaje corto: "Se actualizó la tarea X". Se envía a todos los asignados existentes excepto quien editó.

comment — Al comentar

Aviso de nuevo comentario. No se envía al propio comentador.

reminder — Recordatorio

Generado por reminders.php cuando se acerca la fecha límite.

¿Por qué no hace llamadas al servidor?

Cuando se carga el tablero (loadBoard()), la API kanban.php?action=board devuelve TODO de una vez:

{ "columns": [...], "cards": [...], "tags": [...], "assignees": [...] }

Esto se guarda en variables globales. El calendario simplemente lee esas variables — cero requests extra.

¿Cómo se muestra una tarea en el calendario?

Solo aparece si tiene due_date (fecha límite). Aparece en el día de esa fecha. El chip muestra:

  • Color según prioridad (verde=low, amarillo=medium, naranja=high, rojo=critical)
  • Si no tiene prioridad: el color de la columna
  • El título truncado
  • Mini-avatars con iniciales de los asignados

↓

↓
¿La nueva fecha es anterior al start_date?
↓
No → solo actualiza due_date
Sí → actualiza due_date Y start_date
↓
Actualización optimista: modifica CARDS en memoria → renderCalendar() → el usuario ve el cambio INMEDIATAMENTE
↓

{due_date: 'YYYY-MM-DD'}
↓
MySQL UPDATE cards SET due_date=? WHERE id=?
↓

Código completo de calDrop()

async function calDrop(e, newDateStr) {
    e.preventDefault();
    const cardId = _calDragCardId;
    const card = CARDS.find(c => c.id == cardId);

    // Determinar qué campos actualizar
    const updates = { due_date: newDateStr };
    if (card.start_date && newDateStr < card.start_date) {
        updates.start_date = newDateStr;
    }

    // Actualización optimista (sin esperar al servidor)
    const prevDue = card.due_date;
    card.due_date = newDateStr;
    renderCalendar();

    try {
        await _wsApi(`kanban.php?action=save_card&id=${cardId}`, 'PUT', updates);
    } catch(err) {
        // Si falla, revertir
        card.due_date = prevDue;
        renderCalendar();
    }
}

Stack tecnológico — Programas involucrados

JS

Vanilla JavaScript

Toda la lógica del frontend. Sin frameworks. Funciones globales en index.html.

No necesitás Node.js, npm, ni compilar nada.

PHP

PHP 7.4+

Cada archivo en app/api/ es un endpoint. Usa PDO para la base de datos.

Se ejecuta en el servidor Apache/Nginx del hosting.

MySQL

MySQL 5.7+ / MariaDB

Base de datos relacional. Accedés con phpMyAdmin o HeidiSQL desde tu PC.

WP

WordPress

Solo actúa como "contenedor" del plugin. El panel de admin WP muestra usuarios y notificaciones.

CSS

CSS Variables

Todo el sistema de temas funciona con --acc, --surf, --t1, etc. definidas en :root.

API

CallMeBot API

Servicio externo para WhatsApp. Requiere que cada usuario haga opt-in y obtenga su apikey personal.

Cómo modificar la UI

Todo está en un solo archivo: app/index.html. Tiene tres secciones:

1. CSS (líneas 1–800)

Todo el estilo visual. Variables de color en :root. Cada componente tiene su clase.

2. HTML (líneas 800–1700)

La estructura: topbar, modales, paneles. Todo está en el DOM desde el inicio.

3. JavaScript (líneas 1700–5500)

La lógica: funciones para cada feature. Las funciones están agrupadas con comentarios // ══.

Cómo modificar las APIs

Cada archivo en app/api/ sigue el mismo patrón:

<?php
require_once '../config.php';
$me     = requireAuth();       // valida el token del usuario
$db     = getDB();             // conexión PDO a MySQL
$method = $_SERVER['REQUEST_METHOD']; // GET, POST, PUT, DELETE
$action = $_GET['action'] ?? '';

if ($method === 'GET' && $action === 'mi_accion') {
    // tu código aquí
    $st = $db->prepare("SELECT * FROM ".tb('cards')." WHERE id=?");
    $st->execute([$id]);
    jsonOut(['data' => $st->fetchAll()]);
}

Funciones helpers disponibles en config.php

FunciónQué hace
getDB()Devuelve conexión PDO a admin_luna
requireAuth()Valida token, devuelve array con datos del usuario logueado
requireAdmin()Como requireAuth() pero exige rol admin
tb('nombre')Devuelve el nombre de la tabla con prefijo (LUNA_TB_PREFIX + nombre)

Sistema de Licencias — Cómo funciona

El sistema de licencias conecta cada instalación de Luna Workspace con el servidor central en websobreruedas.com, que actúa como autoridad de validación. Nadie puede usar Luna sin una clave válida asociada a su dominio.

🖥️ Cliente (instalación del cliente)

Cada cliente tiene Luna instalado en su WordPress. Al activar el plugin, ingresa su clave de licencia en el panel WP → Luna Workspace → Licencia.

La clave queda guardada en la opción de WordPress luna_license_key.

🌐 Servidor (websobreruedas.com)

Tu servidor centralizado. Tiene instalado el plugin Luna License Server (un plugin de WP separado) que expone la API REST de validación.

Desde ahí hacés el ABM: crear, suspender, renovar y eliminar licencias de todos tus clientes.

⚠️ El servidor de licencias debe estar online. Si cae websobreruedas.com, las instalaciones en clientes entran en modo offline (usan la cache local) hasta que pueda reconectar.

Verificación desde el lado de la app (index.html)

El frontend también hace su propia verificación al iniciar, independiente del plugin WP:

// Constantes en las primeras líneas de index.html
const LICENSE_SERVER     = 'https://websobreruedas.com/licencias/api/verify.php';
const LICENSE_CACHE_DAYS = 30;  // días de cache en localStorage

// Al iniciar la app:
async function checkLicense() {
    const key    = getLicenseKey();       // desde LUNA_WP.licenseKey o localStorage
    const cached = getLicenseCache();      // si hay cache válida, la usa
    if (cached?.valid) return true;

    // POST al servidor con la clave + dominio del navegador
    const data = await fetch(LICENSE_SERVER, {
        method: 'POST',
        body: JSON.stringify({ license_key: key, domain: window.location.hostname })
    });
    // Si no hay conexión → permite con warning (modo offline)
}

Seguridad: firma HMAC-SHA256

El servidor firma cada respuesta con un secreto compartido para que nadie pueda falsificar una respuesta válida:

// El servidor firma así (websobreruedas.com):
$payload  = implode('|', [$key, $domain, $valid, $plan, $expires_at, $issued_at]);
$hmac     = hash_hmac('sha256', $payload, HMAC_SECRET);

// El cliente (class-luna-license.php) verifica:
$expected = hash_hmac('sha256', $payload, Luna_License::HMAC_SECRET);
if (!hash_equals($expected, $data['hmac'])) {
    // Rechaza — alguien modificó la respuesta o es un servidor falso
    return ['valid' => false, 'reason' => 'invalid_signature'];
}
💡 El HMAC_SECRET en class-luna-license.php y el del servidor deben ser idénticos. Si los cambiás, cambialo en ambos lados al mismo tiempo.

¿Qué pasa si se supera el límite de workspaces?

Al intentar crear un workspace extra, el backend en workspaces.php consulta el límite de la licencia:

// workspaces.php — al crear nuevo workspace:
$lic = getLicenseInfo();
$max = $lic['max_workspaces'] ?? 1;
if ($count >= $max) {
    jsonErr('Límite de workspaces alcanzado para tu plan (' . $max . '). Actualizá tu licencia.', 403);
}

Validación de dominio

Cuando el servidor recibe el POST de verificación, compara el dominio enviado con el que tiene registrado para esa clave:

  • Si coincide → valid: true
  • Si no coincide → valid: false, reason: 'domain_mismatch'
  • Si la clave está en múltiples dominios autorizados → válida para todos ellos (según plan)
⚠️ El dominio se toma de window.location.hostname (en el browser) o de $_SERVER['HTTP_HOST'] (en PHP). Asegurate de que el dominio registrado en websobreruedas.com coincida exactamente (sin www si el sitio no usa www, etc.).

Período de gracia

Cuando una licencia vence, el servidor puede responder con "grace": true, "grace_days": 7. En ese caso:

  • La app sigue funcionando
  • Aparece un banner naranja de aviso en la parte superior con cuenta regresiva
  • La cache de gracia dura solo 1 día (en lugar de 30) para forzar reverificaciones frecuentes

ABM de licencias en websobreruedas.com

Alta — nuevo cliente

  1. Acceder a WP Admin de websobreruedas.com
  2. Luna Licenses → Nueva Licencia
  3. Ingresar: dominio del cliente, plan, fecha de vencimiento
  4. El sistema genera la clave LUNA-XXXX-XXXX-XXXX
  5. Entregarle esa clave al cliente

Baja / Suspensión

  1. WP Admin → Luna Licenses → buscar la clave
  2. Click en "Suspender" o "Eliminar"
  3. La cache del cliente expira en 24hs y la validación fallará
  4. Para suspensión inmediata: el cliente puede limpiar su cache manualmente desde WP Admin → Luna → Licencia → "Limpiar cache"

Modificación / Renovación

  1. WP Admin → Luna Licenses → editar la clave
  2. Cambiar fecha de vencimiento o plan
  3. La cache del cliente se actualiza sola en el próximo ciclo (24hs)
  4. Para renovación inmediata: el cliente limpia la cache desde el panel WP

Cambio de dominio

  1. WP Admin → Luna Licenses → editar la clave
  2. Cambiar el dominio autorizado al nuevo
  3. El cliente instala Luna en el nuevo dominio con la misma clave
  4. El dominio viejo queda automáticamente inválido
